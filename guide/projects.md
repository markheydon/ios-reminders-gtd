## What a project looks like

Open **Projects**, Work section, and you might see:

**Tax return filed**

Notes:

> Submitted and the acknowledgement saved in the tax folder.
>
> Later: pay anything owed. Download the PDF receipt.

Subtasks:

- Gather the interest statements `#anywhere`
- Call the accountant with the questions list `#call`

The parent has no tag and no job except to hold the outcome. The two subtasks are both current: gathering statements does not depend on the call. “Pay anything owed” is written in the notes because it cannot start yet. When the statements are in, you tick that subtask and, if paying is now possible, you add it as a new subtask.

Put the project in the section that matches the area of your life. Move it by dragging, or by editing the reminder if you prefer. The section is how the weekly review walks through your commitments without opening every smart list.

On iPhone and iPad you can show sections as columns: in **Projects**, tap the more button, then **View as Columns**. It is a planning view. Day to day, the context smart lists are quicker.

## How many current next actions

A project should have at least one **next physical action** you can do now, or a `waiting` subtask if something is blocking. More than one subtask is fine when each can be done now without waiting on the others. Later steps belong in the notes until they are real.

Prefer one live subtask when you can. If you dump the whole plan in as subtasks, every context list fills up with work you cannot do yet, and the smart lists stop being trustworthy.

The plan can still be written down. The notes field is the plan. Subtasks are the live edge of it.

Packing is still a project outcome, not a freestanding tagged parent. Under **Projects**, you might have **Trip to Edinburgh** with a subtask **Pack for Thursday** tagged `#home` (or `#anywhere` if you will pack on the sofa). Socks, charger, and passport can be subtasks of that packing step if you want a one-sitting checklist. Give each subtask a context tag at clarify if it is a real next action; leaving checklist lines untagged is your choice at clarify, not a guide-wide exception to one tag per action.

## Waiting

Waiting is still part of the project when the outcome is on **Projects**. You are committed to the outcome, and the current step is “this person, this thing”.

1. Rewrite the subtask so the person comes first: “Priya: photos of the damp patch”.
2. Replace the context tag with `waiting`.
3. Turn on When Messaging if a conversation with them is likely before the review.
4. Add a date if you want **Today** to remind you to nudge them. The **Waiting** smart list will also show the item before that date, which is what you want when you are looking for loose ends.

One-off waits that are not tied to a project outcome can live on **Waiting For** with the same `waiting` tag. The **Waiting** smart list shows project waits and **Waiting For** items together.

The **Waiting** smart list is the cross-project view. **Projects** still shows the same subtask when you open the project, so the story of the work stays in one place.

When what you were waiting for arrives:

- Complete the waiting subtask if the arrival finishes the step, and add the real next action with a context tag.
- Or change `waiting` back to a context tag if the same reminder is now something you can do.

## Someday

**Someday** is for outcomes and ideas you are **not** committed to. Move a whole project there when you want it off your plate: edit the project reminder and change its list to **Someday**. Subtasks move with the parent. Because the context smart lists gather by tag only and **Someday** is not part of those filters, those subtasks disappear from **Anywhere**, **Home**, **Out**, and **Calls** until you bring the project back.

Loose ideas can live as plain reminders in **Someday**, with no tags.

Review **Someday** weekly, in a single pass:

- Delete what you no longer mean.
- Leave what is still “maybe”.
- If you are now committed, move it back to **Projects**, put it in an area, and give it a current tagged subtask.

**Someday** is allowed to be long. It is a parking place, not a second daily list.

## One-step work

“Pay the parking fine” does not need a project. It goes on **Next Actions**, tagged `anywhere` or `out` or whatever the constraint is. It shows up on that smart list beside project subtasks because the tag matches.

If a **Next Actions** item grows a second step, promote it. Create the project with an outcome title, add the current action as a subtask, and complete or delete the **Next Actions** reminder so you do not do the work twice.

## Finished projects

Tick the parent when the outcome is true. Completed reminders can be shown from the more button if you want a moment of proof, then hidden again. You do not need a separate archive list. Recently Deleted keeps accidents for 30 days if you remove something you still needed.

## Horizons above projects

Areas are the sections on **Projects**. Above that - goals for the year, a picture of how you want life to feel, purpose - keep **one note** in the Notes app titled something you will recognise, such as “Horizons”. The weekly review asks you to open it. Pull new projects down from it when something on that page becomes a commitment. Leave the note itself out of Reminders so it is not forever overdue.
